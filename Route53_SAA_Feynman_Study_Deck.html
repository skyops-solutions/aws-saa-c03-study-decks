Розділ 1

DNS та Route 53

Телефонна книга інтернету

Що таке DNS? (як для 5-річного)

Телефонна книга: ім'я → номер

  • Комп'ютери спілкуються через IP-адреси (напр. 93.184.216.34), а люди пам'ятають ІМЕНА (google.com). DNS — це 'телефонна книга', що перекладає ім'я в IP.
  • Route 53 — керований DNS-сервіс AWS (назва від порту 53, на якому працює DNS-протокол).
  • Hosted Zone — контейнер DNS-записів для одного домену (напр. 'example.com') — аналог 'сторінки' у телефонній книзі.
  • TTL (Time To Live) — скільки часу клієнтські DNS-резолвери можуть КЕШУВАТИ відповідь, перш ніж питати знову — менший TTL = швидші зміни, але більше запитів до Route 53.
EXAM TIPRoute 53 — це НЕ просто DNS, а DNS + 'логіка маршрутизації' (health checks, failover, geo-based відповіді) — саме це робить його потужним для Solutions Architect.
1. DNS та Route 53 Basics

CNAME vs Alias Record

Класична пастка іспиту

  • CNAMEстандартний DNS-запис 'псевдонім → інше ім'я'; НЕ можна використовувати для кореневого домену (apex, напр. 'example.com' без www).
  • Alias RecordAWS-специфічне розширення; працює як CNAME, але МОЖНА використовувати на apex-домені, і вказує НАПРЯМУ на AWS-ресурси (ALB, CloudFront, S3 website, інший Route 53 record) без додаткової DNS-подорожі.
  • Alias — безкоштовнийзапити до Alias records НЕ тарифікуються Route 53, на відміну від звичайних A/CNAME записів.
EXAM TIP'Потрібно направити КОРЕНЕВИЙ домен (example.com, без www) на ALB' → CNAME тут технічно заборонений DNS-стандартом, потрібен Alias Record.

Routing Policies: Simple, Weighted, Latency

Перші 3 з 7 стратегій маршрутизації

Simple, Weighted, Latency

Базові стратегії розподілу трафіку

  • Simple Routingодин запис → одна (або кілька, обраних випадково) IP-адреса; немає health checks, найпростіший варіант.
  • Weighted Routingрозподіляє трафік за ВІДСОТКАМИ між кількома ресурсами (напр. 90% на стару версію, 10% на нову) — ідеально для canary deployments чи A/B тестування.
  • Latency-based Routingнаправляє користувача до РЕГІОНУ з найменшою мережевою затримкою (latency) для НЬОГО конкретно — не обов'язково географічно найближчого!
EXAM TIP'Latency-based' — це про РЕАЛЬНУ мережеву швидкість, виміряну AWS, а не про фізичну відстань — іноді географічно далі, але з кращим маршрутом = менша latency.

Порівняльна таблиця решти стратегій

Найважливіша таблиця розділу

PolicyЩо робитьТиповий сценарій
FailoverНаправляє на PRIMARY, поки Health Check 'зелений'; автоматично перемикає на SECONDARY при збоїActive-passive DR-архітектура
GeolocationМаршрутизація за КРАЇНОЮ/континентом користувача (не latency, а фізичне розташування)Юридичні обмеження контенту, локалізований контент за країною

3. Routing Policies (частина 2)

Route 53 Health Checks

Як Route 53 дізнається, що ресурс 'здоровий'

  • Health Check регулярно опитує endpoint (HTTP/HTTPS/TCP) і позначає його Healthy/Unhealthy.
  • Можна перевіряти навіть CloudWatch Alarm замість прямого HTTP-запиту — корисно для перевірки внутрішніх метрик (напр. 'кількість помилок у застосунку').
  • Failover Routing НАПРЯМУ залежить від Health Check: без нього Route 53 не знає, коли перемикатись на secondary.
EXAM TIP'Хочемо переключатись на backup-регіон автоматично при падінні основного' → Failover Routing Policy + Health Check — обов'язково РАЗОМ.

Розділ 4

Route 53 Resolver

Коли on-premises і AWS повинні розв'язувати ІМЕНА ОДНЕ ОДНОГО

Проблема гібридного DNS

Дві окремі 'телефонні книги', які не бачать одна одну

  • У гібридній мережі (частина інфраструктури on-premises, частина в AWS VPC) виникає проблема: сервер у VPC не знає, як розв'язати внутрішнє ім'я 'db.corp.local' з on-premises DNS-сервера, і навпаки — on-premises сервер не бачить внутрішні AWS-імена.
  • Route 53 Resolver — це вбудований DNS-резолвер, який ЗАВЖДИ автоматично існує в кожній VPC (на адресі VPC CIDR + 2), але за замовчуванням розв'язує ЛИШЕ AWS-внутрішні імена.
4. Route 53 Resolver: гібридний DNS

Inbound та Outbound Resolver Endpoints

Два 'мости' для двостороннього гібридного DNS

  • Outbound Endpointдозволяє ресурсам У VPC надсилати DNS-запити НАЗОВНІ, на on-premises DNS-сервер (напр. для імен 'corp.local') — 'запит виходить з AWS'.
  • Inbound Endpointдозволяє on-premises серверам надсилати DNS-запити ВСЕРЕДИНУ VPC, щоб розв'язати AWS-внутрішні імена (напр. приватні DNS-імена RDS) — 'запит заходить в AWS'.
  • Разомці два ендпоінти дають ПОВНОЦІННИЙ двосторонній гібридний DNS: on-premises і AWS 'бачать' і розв'язують імена одне одного.
ЗАПАМ'ЯТАЙ'On-premises сервери повинні розв'язувати внутрішні AWS DNS-імена' → Inbound Resolver Endpoint. 'AWS-ресурси повинні розв'язувати внутрішні on-premises DNS-імена' → Outbound Resolver Endpoint. Напрямок назви ендпоінта — це напрямок, звідки ПРИХОДИТЬ запит.

Підсумок: Route 53 одним поглядом

  • DNS перекладає імена в IP-адреси; Alias Record (безкоштовний, підтримує apex domain) кращий за CNAME на AWS
  • Simple / Weighted / Latency-based — базові стратегії розподілу за відсотками чи мережевою швидкістю
  • Failover (потребує Health Check) / Geolocation (юридичні обмеження) / Geoproximity (bias за відстанню) / Multi-Value / IP-based
  • Health Checks — обов'язкова умова для Failover Routing і корисні для моніторингу здоров'я endpoint'ів
