Розділ 1

Amazon CloudFront

CDN — доставка контенту ближче до користувача

Що таке CDN? (аналогія)

Локальні складські філії замість одного центрального складу

  • Уяви інтернет-магазин з ОДНИМ складом у Києві — клієнт з Токіо чекає доставку тижнями.
  • Якщо відкрити 'філії' (кеш-копії) по всьому світу — клієнт отримує товар з НАЙБЛИЖЧОЇ філії за хвилини.
  • CloudFront — це мережа Edge Locations (сотні точок присутності по всьому світу), які кешують копії твого контенту БЛИЗЬКО до користувачів.
  • Origin (джерело) — це S3, ALB/EC2, або будь-який HTTP-сервер, звідки CloudFront бере оригінальний контент при першому запиті (cache miss).
EXAM TIPCloudFront зменшує latency (контент ближче до користувача) і розвантажує origin-сервер (повторні запити обслуговуються з кешу, не доходячи до origin).
1. Amazon CloudFront

Origins: S3 vs Custom Origin (ALB/EC2)

Дві основні конфігурації

  • S3 Originстатичні файли (сайти, зображення, відео); доступ через Origin Access Control (OAC) — бакет лишається ПРИВАТНИМ, доступ тільки через CloudFront.
  • Custom Origin (ALB/EC2/будь-який HTTP)динамічний контент (API, серверний рендеринг); можна кешувати навіть динамічні відповіді за правилами Cache Policy.
  • Geo Restrictionдозволяє/забороняє доступ до контенту за країною користувача (allowlist/blocklist) — для ліцензійних/юридичних обмежень.
  • Cache Invalidationпримусово 'скидає' кешовану версію конкретного шляху (напр. після оновлення файлу) — платна операція понад безкоштовний ліміт.
ЗАПАМ'ЯТАЙ'S3-бакет має бути ПРИВАТНИМ, а користувачі отримують доступ тільки через HTTPS' → CloudFront + Origin Access Control (OAC) перед приватним бакетом.

Просунуті фічі CloudFront

Часто в сценаріях іспиту

ФічаЩо робить
Signed URLs / Signed Cookiesобмежують доступ до контенту (напр. платне відео) — схоже на S3 Presigned URL, але на рівні CloudFront

Field-Level Encryption шифрує КОНКРЕТНЕ поле (напр. номер картки) ще на Edge Location — і воно лишається зашифрованим навіть всередині origin-сервера, захищаючи від зловмисного адміна, витоку логів чи компрометації самого origin

1. Amazon CloudFront

TTL та Cache-Control — як CloudFront вирішує, коли 'освіжити' кеш

Механіка, а не просто цифра

  • TTL (Time To Live) — це НЕ вигадана CloudFront цифра 'з повітря': за замовчуванням CloudFront читає HTTP-заголовок Cache-Control (або Expires), який повертає origin-сервер разом з файлом, і кешує саме на цей термін.
  • Якщо origin взагалі не вказав Cache-Control — CloudFront використовує Default TTL, заданий у налаштуваннях Behavior (типово 24 год).
  • Cache-Control: no-cache (чи max-age=0) від origin означає 'перевіряй свіжість при КОЖНОМУ запиті' — CloudFront усе одно може закешувати, але зобов'язаний спитати origin 'чи є новіша версія' перед тим, як віддати збережену копію.
ЗАПАМ'ЯТАЙ'Контент повинен оновлюватись МАЙЖЕ миттєво після зміни на origin' → зменшити Cache-Control max-age (чи поставити no-cache) НА ORIGIN, а не покладатись лише на ручну Cache Invalidation після кожної зміни.

AWS Global Accelerator

Прискорення мережевого шляху через магістральну мережу AWS

Що робить Global Accelerator? (аналогія)

Виділена швидкісна автомагістраль замість звичайних доріг

  • Уяви, що замість того, щоб трафік користувача 'блукав' звичайним публічним інтернетом до найближчого AWS-регіону, він одразу потрапляє на ШВИДКІСНУ приватну магістраль AWS.
  • Global Accelerator дає ДВІ статичні Anycast IP-адреси — трафік користувача заходить у найближчу Edge Location AWS і далі йде приватною мережею AWS до потрібного регіону.
  • На відміну від CloudFront, Global Accelerator НЕ кешує контент — він лише прискорює МАРШРУТ до твого застосунку (ALB, NLB, EC2, Elastic IP). Пастка: Global Accelerator НЕ підтримує S3 як пряме джерело (endpoint) — якщо потрібно прискорити доступ до S3, використовуй CloudFront, а не GA.
  • Автоматичний failover: якщо застосунок в одному регіоні 'падає' (health check), трафік миттєво перенаправляється в здоровий регіон — БЕЗ зміни IP-адреси для клієнта.
EXAM TIPCloudFront кешує статичний/динамічний КОНТЕНТ. Global Accelerator прискорює й робить відмовостійким сам МЕРЕЖЕВИЙ ШЛЯХ (для TCP/UDP, не тільки HTTP).

2. AWS Global Accelerator

Підсумок: CloudFront & Global Accelerator одним поглядом

  • CloudFront: CDN, кешує контент на Edge Locations, S3 Origin через OAC для приватних бакетів
  • Signed URL/Cookies для обмеженого доступу, Lambda@Edge для логіки близько до користувача
  • Global Accelerator: прискорює мережевий ШЛЯХ (не кешує), статичні Anycast IP, працює з будь-яким TCP/UDP
  • CloudFront = 'контент ближче до користувача'. Global Accelerator = 'швидша й надійніша дорога до застосунку'

Якщо в задачі є слово 'кешування' або 'статичний веб-контент' → CloudFront. Якщо 'статична IP' або 'не-HTTP протокол' → Global Accelerator.
