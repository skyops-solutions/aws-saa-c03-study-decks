Розділ 1

Private, Public та Elastic IP

Три різні типи IP-адрес EC2 — і чому це плутають

Три типи адрес (аналогія)

Внутрішній номер офісу vs номер готелю vs особистий мобільний

  • Private IP'внутрішній номер офісу' — адреса ВСЕРЕДИНІ твоєї VPC (напр. 10.0.1.5), не змінюється, доки інстанс не термінований; видно тільки в межах VPC.
  • Public IP'номер готельного номера' — видається автоматично при запуску (якщо увімкнено auto-assign), але змінюється КОЖЕН РАЗ при Stop/Start інстансу — це головна пастка!
  • Elastic IP'твій особистий мобільний номер' — статична публічна IP-адреса, яку ти сам 'бронюєш' і прикріплюєш до інстансу; лишається ЗА ТОБОЮ навіть після Stop/Start чи заміни інстансу.
EXAM TIP'Публічна IP-адреса змінилась після перезапуску інстансу, і зовнішній DNS-запис зламався' — класична пастка. Рішення: використовувати Elastic IP (або, ще краще, DNS-ім'я через Route 53/ELB).
1. Private vs Public vs Elastic IP

Коли що використовувати

Практичні висновки

  • Elastic IP коштує грошей, ЯКЩО він НЕ прикріплений до працюючого інстансу (AWS свідомо 'штрафує' за невикористані зарезервовані публічні адреси — вони дефіцитні).
  • AWS рекомендує МІНІМІЗУВАТИ використання Elastic IP там, де можна — краще використовувати DNS-ім'я (Route 53) або Load Balancer, що вирішують проблему 'стабільної точки входу' елегантніше.
  • Ліміт: 5 Elastic IP на регіон за замовчуванням (можна збільшити запитом до AWS Support).
EXAM TIP'Потрібна стабільна публічна IP для одного конкретного сервера (напр. legacy-застосунок, що очікує фіксовану IP)' → Elastic IP. Але для сучасної архітектури зазвичай краще ELB/Route 53.

EC2 Placement Groups

Керуємо ФІЗИЧНИМ розташуванням інстансів

Навіщо керувати розташуванням? (аналогія)

Сусідні кімнати в готелі vs розкидані по різних поверхах

  • За замовчуванням AWS сам вирішує, на яких фізичних серверах розмістити твої інстанси — тобі це зазвичай байдуже.
  • Але іноді ФІЗИЧНА близькість (чи навпаки, віддаленість) серверів одне від одного критично важлива — і Placement Group дає над цим контроль.
  • Уяви команду, якій потрібно спілкуватись пошепки (низька latency) — їх варто посадити в СУСІДНІ кімнати. А команду, де важлива відмовостійкість — навпаки, розкидати по РІЗНИХ будівлях, щоб одна пожежа не знищила всіх.
2. Placement Groups

3 типи Placement Group

Таблиця для іспиту

  • Clusterусі інстанси на ОДНОМУ 'стійці' (rack), максимально близько фізично → найнижча можлива мережева latency й найвищий throughput між ними. Ризик: якщо стійка/AZ впаде — ВСІ інстанси падають разом. Для HPC, обчислень, що вимагають швидкого обміну даними між вузлами.
  • Spreadкожен інстанс на ОКРЕМОМУ фізичному хості (і навіть можна розкидати по РІЗНИХ AZ) → максимальна ізоляція від апаратних збоїв. Ліміт: 7 інстансів на AZ у групі. Для критичних, невеликих за кількістю інстансів, де відмова ОДНОГО фізичного хоста не повинна зачепити інші.
  • Partitionінстанси розбиті на 'партиції' (до 7), кожна на ОКРЕМОМУ наборі стійок — збій однієї партиції не чіпає інші. Для великих розподілених систем (Hadoop, Kafka, Cassandra), де сама система вже знає про 'партиції' і реплікує дані між ними.
ЗАПАМ'ЯТАЙКлючові слова: 'найнижча мережева latency між вузлами' → Cluster. 'Максимальна ізоляція від апаратних збоїв, невелика кількість критичних інстансів' → Spread. 'Велика розподілена система з власною реплікацією (Hadoop/Cassandra)' → Partition.

Розділ 3

Elastic Network Interfaces та EC2 Hibernate

Віртуальні мережеві картки й 'сон' для інстансів

Elastic Network Interface (ENI)

Віртуальна мережева картка, яку можна 'відкрутити' й переставити

  • ENI — це логічний компонент віртуальної мережевої картки в VPC: має свою Private IP, опційно Public/Elastic IP, Security Groups, MAC-адресу.
  • Головна фішка: ENI можна ВІД'ЄДНАТИ від одного EC2-інстансу і ПРИКРІПИТИ до іншого (в тій самій AZ) — усі мережеві налаштування (IP, SG) 'переїжджають' разом з нею.
  • Типове застосування: якщо основний інстанс падає, можна швидко переключити ENI (а разом з нею — всі IP-адреси й правила SG) на резервний/новий інстанс замість того, щоб все перенастроювати вручну.
  • Кожен EC2-інстанс має ОСНОВНИЙ (primary) ENI за замовчуванням, і можна додати ДОДАТКОВІнавіщо: уяви сервер, де 'адміністративний' SSH-доступ і 'клієнтський' трафік застосунку йдуть ЧЕРЕЗ ОДНУ й ту саму мережеву картку з ОДНИМИ Security Group правилами — важко обмежити, хто саме бачить порт адміністрування. Додаткова ENI дозволяє фізично розділити ці потоки: одна ENI (зі своїми SG) тільки для управління/моніторингу, інша — тільки для трафіку клієнтів, кожна зі СВОЇМИ правилами доступу і навіть окремим лімітом пропускної здатності.
ЗАПАМ'ЯТАЙ'Потрібно швидко замінити невиправний інстанс, зберігши всі мережеві налаштування (IP-адреси)' → від'єднати ENI від старого інстансу і прикріпити до нового.
3. ENI & EC2 Hibernate

EC2 Hibernate

'Сон' інстансу замість повного вимкнення

  • Звичайний Stop: ОС вимикається повністю, вміст оперативної пам'яті (RAM) втрачається — наступний запуск = 'холодний старт' застосунку заново.
  • Hibernate: вміст RAM зберігається на root EBS volume ПЕРЕД зупинкою (як 'режим сну' на ноутбуці) — при наступному запуску ОС і застосунок відновлюються ТОЧНО там, де зупинились, без повторної ініціалізації.
  • Корисно для застосунків з довгим 'холодним стартом' (напр. великі in-memory кеші, складна ініціалізація сервісу) — не треба щоразу 'розігрівати' стан заново.
  • Обмеження: підтримується не для всіх instance families, root volume має бути EBS (не Instance Store), і RAM повинна поміщатись у вільне місце на root volume.
ЗАПАМ'ЯТАЙ'Застосунок довго 'прогрівається' після кожного запуску (розігрів кешу, JIT-компіляція) і хочемо уникнути цього' → EC2 Hibernate замість звичайного Stop/Start.

Підсумок: EC2 Advanced одним поглядом

  • Private IP (постійна, внутрішня) vs Public IP (змінюється при Stop/Start) vs Elastic IP (статична, платна, якщо не використовується)
  • Placement Groups: Cluster (найнижча latency, ризиковано) / Spread (максимальна ізоляція) / Partition (для великих розподілених систем)
  • ENI: 'віртуальна мережева картка', яку можна переставляти між інстансами разом з IP і SG
  • EC2 Hibernate: зберігає стан RAM на диск — 'сон' замість повного вимкнення, уникає 'холодного старту'

Ці деталі рідше зустрічаються, ніж базовий EC2, але саме вони відрізняють 'просто знаю EC2' від 'розумію нюанси Solutions Architect рівня'.
