EC2 Basics

Amazon Elastic Compute Cloud — фундамент

Що таке EC2? (поясни як для 5-річного)

Проста аналогія

  • Уяви, що тобі потрібен комп'ютер для проекту, але купувати його дорого і довго.
  • EC2 — це як "оренда комп'ютера" в AWS: береш потрібну потужність (CPU/RAM), платиш лише за час користування, і можеш вимкнути коли не треба.
  • Технічно: EC2 = Elastic Compute Cloud — віртуальний сервер (Virtual Machine) в хмарі AWS.
  • "Elastic" — бо можна легко змінити розмір (scale up/down) або кількість (scale out/in).
EXAM TIPEC2 — це базовий сервіс IaaS (Infrastructure as a Service): ти керуєш ОС, а AWS керує "залізом".
1. EC2 Basics

З чого складається інстанс EC2

Базові будівельні блоки

  • AMI (Amazon Machine Image)шаблон "знімок" ОС + встановлений софт, з якого запускається інстанс.
  • Instance Typeскільки vCPU / RAM / мережі виділено (напр. t3.micro).
  • EBS Root Volumeвіртуальний диск, де живе ОС (persistent, не зникає при stop).
  • Security Groupfirewall на рівні інстанса — які порти/IP дозволені.
  • Key Pairпублічний/приватний ключ для SSH/RDP доступу замість пароля.
  • User Dataскрипт, що виконується один раз при першому старті (bootstrap).
EXAM TIPUser Data виконується від імені root/Administrator і має ліміт 16 KB (base64).

1. EC2 Basics

EBS-backed vs Instance Store-backed

Найважливіша різниця для іспиту

  • EBS-backed (за замовчуванням)Root volume — це EBS. Можна Stop/Start — дані зберігаються. Можна змінити instance type під час stop.
  • Instance Store-backedRoot volume фізично "прибитий" до хоста (ephemeral). Stop недоступний — тільки Terminate. При збої хоста дані ЗАВЖДИ втрачаються.
EXAM TIPЯкщо інстанс Instance Store-backed — 'Stop' в UI буде недоступний або еквівалентний Terminate. Дані зникають назавжди.
1. EC2 Basics

Instance Metadata Service (IMDS) та атака, яку блокує IMDSv2

Найважливіше security-питання цього розділу

  • Кожен EC2-інстанс може звернутись до спеціальної внутрішньої адреси 169.254.169.254 і отримати інформацію про себе (свій instance ID, і — найважливіше — ТИМЧАСОВІ IAM-креденшели своєї IAM Role).
  • Проблема IMDSv1: щоб отримати ці креденшели, достатньо було ЗВИЧАЙНОГО GET-запиту без жодної автентифікації. Якщо на інстансі працює вразливий веб-застосунок із SSRF-вразливістю (Server-Side Request Forgery — коли зловмисник змушує сервер зробити запит за URL, який ВІН підказав), зловмисник просто підставляє URL 'http://169.254.169.254/latest/meta-data/iam/security-credentials/...' — і застосунок сам, невинно, приносить йому IAM-креденшели інстансу.
  • З цими вкраденими креденшелами зловмисник далі діє в AWS-акаунті з правами тієї IAM Role (читає S3, EC2, тощо) — це один із найвідоміших реальних векторів злому в хмарі.
  • IMDSv2 закриває цю дірку: тепер ПЕРЕД читанням метаданих потрібно спочатку зробити PUT-запит, щоб отримати сесійний токен, і лише З ЦИМ токеном робити GET. Проста SSRF-вразливість, що вміє підставити лише URL в GET-запиті (найпоширеніший тип SSRF), більше не може виконати потрібний PUT-крок — і атака ламається.
EXAM TIPIMDSv2 не 'взагалі забороняє' читати метадані — він лише вимагає ДОДАТКОВИЙ крок (PUT за токеном), який типова SSRF-вразливість технічно не вміє відтворити.

EC2 Instance Types

Обираємо правильний "розмір одягу" для навантаження

Як читати назву інстансу

m5.2xlarge — розбір по літерах

  • mродина (family) — визначає баланс CPU/RAM/Network/Storage.
  • 5покоління (generation) — новіше зазвичай дешевше і швидше.
  • 2xlargeрозмір — кратно подвоює vCPU/RAM відносно 'large'.
  • Додаткові літери:n = network optimized, d = локальний NVMe SSD, a = AMD CPU, g = AWS Graviton — власний ARM-процесор AWS. ARM-архітектура фізично споживає менше електроенергії на ту саму обчислювальну роботу, ніж традиційні x86 (Intel/AMD) чіпи — менше електрики й охолодження для AWS означає нижчу собівартість, яку AWS передає тобі у вигляді ціни на ~20% нижчої за еквівалентний x86-інстанс.
EXAM TIPАналогія: family = 'модель авто' (седан/вантажівка/спорткар), generation = 'рік випуску', size = 'об'єм двигуна'.
2. Instance Types

5 родин інстансів

Головна класифікація на іспиті

  • General Purpose (M, T, A, Mac)баланс CPU/RAM/Network — веб-сервери, невеликі БД, dev/test.
  • Compute Optimized (C)багато vCPU — batch processing, HPC, gaming servers, media transcoding.
  • Memory Optimized (R, X, z1d)багато RAM — in-memory кеші, SAP HANA, real-time big data.
  • Storage Optimized (I, D, H)високий IOPS/локальний NVMe — NoSQL (Cassandra), data warehousing.
EXAM TIPКлючові слова в завданні → підказка родини: 'in-memory'/'cache' → R; 'video encoding'/'ML inference' → C/G; 'high-frequency trading' → C/z1d.
2. Instance Types

T-родина: Burstable Performance

Дуже частий сюжет на іспиті

  • T-інстанси (t2/t3/t3a/t4g) мають baseline рівень CPU (наприклад 20-40%).
  • Коли навантаження НИЖЧЕ baseline — накопичуються CPU Credits.
  • Коли навантаження ВИЩЕ baseline — витрачаються накопичені credits (burst).
  • Standard modeколи credits закінчились — продуктивність "придушується" (throttle) до baseline.
  • Unlimited modeколи credits закінчились — можна перевищувати baseline, але за додаткову плату.
EXAM TIPДодаток 'раптово гальмує' на T-інстансі під сталим високим навантаженням = вичерпались CPU credits. Рішення: Unlimited mode або перехід на M/C родину.

Security Groups & Classic Ports

Вбудований firewall для EC2

Security Group — аналогія

Охоронець на вході

  • Уяви охоронця на вході у будівлю, який має список "кому можна зайти" (allow list).
  • Він НЕ має списку "кому заборонено" — просто якщо тебе нема у списку, ти не заходиш.
  • Security Group (SG) — це саме такий список правил, прикріплений до мережевого інтерфейсу (ENI) інстанса.
  • SG перевіряє тільки вхідний напрямок за замовчуванням заблокований, вихідний — за замовчуванням дозволений весь.
EXAM TIPSG = allow-only (немає 'deny' правил). Це головна відмінність від Network ACL.
3. Security Groups

Ключові властивості SG

Те, що завжди перевіряють на іспиті

  • Statefulякщо дозволив вхідний запит — відповідь автоматично дозволена (не треба окремого outbound правила).
  • Рівень: інстанс (ENI), не підмережана відміну від NACL, який працює на рівні subnet.
  • Кілька SG на інстансправила з усіх прикріплених SG об'єднуються (найбільш дозвільне перемагає).
  • SG як джерело (source)можна вказати інший Security Group ID замість CIDR — зручно для 'дозволити тільки з ALB'.
  • Default SGзабороняє весь inbound, дозволяє весь outbound.

3. Security Groups

SG vs NACL — типова пастка іспиту

Timeout vs Refused

  • "Connection timed out"трафік десь блокується мовчки (SG не дозволяє, NACL блокує, або немає route/IGW). Пакет просто "губиться".
  • "Connection refused"мережевий доступ є (SG/NACL дозволяють), але сервіс на інстансі не слухає цей порт, або локальний firewall ОС (iptables/Windows Firewall) відхиляє.
  • Network ACL (для порівняння)працює на рівні підмережі, stateless (треба окремо дозволяти inbound І outbound), підтримує allow ТА deny, правила виконуються по номеру за зростанням.
EXAM TIPЯкщо після зміни SG все одно не працює — перевір NACL, Route Table, а потім firewall всередині ОС.

EC2 Purchasing Options & Spot

Як платити за EC2 розумно

Аналогія з квитками на літак

5 способів "купити" EC2

  • On-Demand — повний гнучкий тариф: летиш коли хочеш, платиш більше.
  • Reserved / Savings Plans — бронюєш заздалегідь на 1-3 роки, суттєва знижка, менше гнучкості.
  • Spot — 'standby' квиток за копійки, але можуть "зняти з рейсу" (interruption), якщо місце знадобиться комусь, хто платить повну ціну.
  • Dedicated Host/Instance — орендуєш весь літак (фізичний сервер) собі.
  • Capacity Reservation — бронюєш саме місце (капасіті) в AZ, платиш навіть якщо не летиш.
EXAM TIPГоловне на іспиті: підбирати опцію під характер навантаження (steady-state vs spiky vs fault-tolerant vs compliance).

4. Purchasing Options

Spot Instances

До 90% знижки — з нюансами

  • Spot Price змінюється залежно від попиту/пропозиції вільної капасіті AWS.
  • InterruptionAWS може забрати інстанс з 2-хвилинним попередженням через CloudWatch Event / instance metadata.
  • Причини interruptionprice (перевищив максимум), capacity (потрібна AWS), constraint, AZ rebalance.
  • Ідеально дляbatch jobs, big data (EMR), CI/CD, stateless веб-сервери, рендеринг, fault-tolerant задачі.
  • НЕ підходить длякритичні бази даних, стани без чекпоінтів.
EXAM TIPSpot НІКОЛИ не гарантує доступність — це найдешевше, але найменш надійне рішення. Завжди думай про 'fault-tolerant' у формулюванні задачі.
4. Purchasing Options

Spot Fleet & стратегії розподілу

Групуємо Spot-пули розумно

  • Spot Fleetнабір Spot (і опційно On-Demand) пулів різних instance type/AZ, що разом досягають цільової капасіті.
  • lowest-priceзапускає найдешевші доступні пули (може часто перериватись).
  • diversifiedрівномірно розподіляє по пулах — стійкість до перерваних пулів.
  • capacity-optimizedобирає пули з найбільшою доступною капасіті — менше interruption.
  • price-capacity-optimizedновіша рекомендована стратегія AWS: баланс ціни та стабільності капасіті.
ЗАПАМ'ЯТАЙНайкраща практика (і улюблене питання іспиту): комбінувати базовий On-Demand/Reserved 'фундамент' + Spot Fleet для 'сплесків' навантаження.

Підсумок: 4 теми одним поглядом

  • EC2 Basics: AMI + Instance + EBS + SG + Key Pair + User Data = твій сервер в оренду
