Як обрати правильну базу даних

Фреймворк рішень — найчастіша "прихована" частина сценарних питань

Питання, які треба поставити (аналогія)

Уяви, що ти лікар, а не інженер

  • Уяви лікаря, який спершу питає симптоми, а не одразу виписує ліки.Так само з БД: спершу питання про workload, а не одразу "бери DynamoDB бо модно".
  • Read-heavy, write-heavy чи balanced? Throughput стабільний чи флуктуює протягом дня?
  • Скільки даних і як довго зберігати? Середній розмір об'єкта? Як до них звертаються?
  • Durability даних? Де "джерело правди" (source of truth)?
  • Вимоги до latency? Скільки одночасних юзерів?
  • Модель даних: JOIN-и потрібні? Структуровані/напівструктуровані? Строга схема чи гнучкість?
EXAM TIPЯкщо в сценарії згадують "JOIN-и" і "складні транзакції" — це майже завжди RDBMS (RDS/Aurora). Якщо "мільйони дрібних JSON-документів, milliseconds latency" — це DynamoDB.

Розділ 2

Amazon DynamoDB

Serverless NoSQL з latency в мілісекундах

Що таке DynamoDB? (аналогія)

Проста аналогія

  • Уяви шафу з шухлядами, де на кожній шухляді написаний унікальний ярлик (Partition Key) — щоб миттєво знайти потрібну шухляду, не перебираючи всі.
  • DynamoDB — власна (proprietary) технологія AWS, НЕ open-source, повністю serverless NoSQL база.
  • На відміну від RDS, тут немає інстансу, який ти адмініструєш — тільки таблиця, ключі та capacity.
  • Дані зберігаються як JSON-подібні документи (Items), без строгої схеми для не-ключових атрибутів.
  • Highly Available за замовчуванням, Multi-AZ "з коробки" — на відміну від RDS, де Multi-AZ треба вмикати явно.
EXAM TIPDynamoDB може ПОВНІСТЮ замінити ElastiCache як key/value store для session data — через TTL-фічу. Це часта пастка вибору "правильної" відповіді.
2. Amazon DynamoDB

Capacity, DAX, Streams, Global Tables

4 речі, які точно спитають на іспиті

  • Capacity Modes: Provisioned (з опційним auto-scaling) АБО On-Demand (плати за фактичне використання, нуль планування).
  • DAX (DynamoDB Accelerator)окремий in-memory кеш-кластер ПЕРЕД DynamoDB — знижує latency до мікросекунд для read-важких навантажень.
  • DynamoDB Streamsвпорядкована послідовність змін у таблиці — інтегрується з Lambda чи Kinesis Data Streams для event-driven обробки.
  • Global Tablesactive-active мульти-регіональна реплікація — запис в будь-якому регіоні реплікується у всі інші.
  • Backup: автоматичні бекапи до 35 днів з PITR (point-in-time restore), або on-demand бекапи без ліміту.
EXAM TIP"DAX" ≠ "ElastiCache перед DynamoDB" — це РІЗНІ сервіси. DAX працює ТІЛЬКИ з DynamoDB API, ElastiCache — універсальний кеш для будь-якої БД.

Підсумок: Databases in AWS одним поглядом

  • Спершу питання про workload (read/write, latency, JOIN-и, схема) — ПОТІМ вибір сервісу
  • DynamoDB: serverless NoSQL, DAX для мікросекундного read-кешу, Streams для event-driven, Global Tables для active-active мульти-регіону
  • DynamoDB МОЖЕ замінити ElastiCache для session storage (через TTL) — але DAX ≠ ElastiCache
  • Спеціалізовані БД — це "AWS-версії" відкритих стандартів: DocumentDB=MongoDB, Keyspaces=Cassandra, Neptune=Graph, Timestream=Time Series

DynamoDB — один з найбільш тестованих сервісів іспиту. Не пропускай цю тему.
